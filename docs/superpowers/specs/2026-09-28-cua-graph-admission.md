# Request-aware CUDA Graph admission

User-approved scope: fix #24 review findings, implement admission/cooldown/capture budget, validate on the RTX 4090, publish a PR and evidence, then shut down the server.

The optional Graph worker keeps exact layouts and segmented capture. Count a layout once per predict request, require two request observations no more than eight requests apart, and forget old sparse observations. Cached hits are always usable. On eviction discard accumulated heat and impose a 32-request cooldown. Bound metadata to 128 layouts. Budget at most four capture attempts and 2000 ms of completed capture-attempt work in any sliding 32-request window. One synchronous capture cannot be preempted; its elapsed time may overshoot the time budget, after which subsequent attempts use eager. Failures consume budget too. Model invalidation clears policy state. Explicit request contexts serialize complete Graph predictions and restore state on errors; standalone forward calls without context fall back eagerly.

Keep --graph opt-in; expose policy limits and clarify min-uses now counts requests. No padding, new kernels, concurrency, or upstream full-attention numerical fix. Compare eager, legacy #24 admission, and new admission with cold caches, identical inputs, alternating order, all-response parity, and captured/uncaptured layout evidence. Extend churn beyond the former eight-use blind spot. Report total/p50/p95, post-capture sustained break-even, captures/evictions, fallback causes and memory. Small differences without graph replay are timing variation.

Extended GPU testing exposed an inherited graph-lifetime hazard on installed torch commit `08187d9e0fba026dc8217405802ab5381dc88d90`: CUDAGraph reset clears cuBLAS workspace by capture stream. Default shared-stream captures therefore couple independent entries. A minimal surviving-graph reproduction fails with a shared stream and passes with independently owned external streams (upstream pytorch/pytorch#193402). Add an exclusively owned CUDA capture stream per segment, using cudaStreamCreate/ExternalStream rather than the 32-stream pool, and explicit synchronization/reset/tensor-release/destroy cleanup. Test more than 32 simultaneously live segments and replay after eviction. The final policy comparison applies this same lifecycle repair to the historical admission policy; preserve the failed untouched-legacy run separately and label the control accurately.

The complete September 29 matrix with per-segment owned streams exposed capture-OOM fallback despite exact responses. Live-tensor deltas understated private-pool reservations. Share one pool and exclusive stream across sequential segments of each shape, preserving capture/replay order and whole-shape retirement, while isolating different shapes. Account full private-pool reserved segments plus external static buffers against max_bytes. Native allocator is required for this accounting; unsupported allocators recover eagerly. Candidate capture peaks may exceed resident-cache limits. Apply the same _ShapeEntry/_run_segments/execution and accounting to the historical policy comparator and rerun all final evidence; retain OOM results only as diagnostics.
