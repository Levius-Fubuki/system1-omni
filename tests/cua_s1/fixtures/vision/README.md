# Pinned vision metadata fixtures

These fixtures are an independent test oracle captured from upstream metadata,
not generated by the production Rust inventory builder:

- Base: `Qwen/Qwen3.5-4B`, revision
  `851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a`.
- Adapter: `cua-ai/cua-s1-4b-0.2`, revision
  `16818868b0cc7813808aae4e87b417657046ab79`, multimodal adapter.
- `config.json` and `adapter_config.json`: upstream configuration files with LF line endings.
- `base-tensors.json`: visual names, shapes, and dtypes read from the pinned
  base safetensors headers (prefix `model.visual.`): 297 BF16 tensors.
- `adapter-tensors.json`: visual names, shapes, and dtypes read from the pinned
  multimodal adapter safetensors header (prefix
  `base_model.model.model.visual.`): 100 FP32 tensors / 50 LoRA pairs.

No weight payloads are included. Tests construct sparse files with these shapes
and sentinel values. Production code never reads these fixtures. Fixture
matching proves structural compatibility, not checkpoint identity: verify real
checkpoint downloads against trusted upstream hashes separately.

Exact pinned sources:

- [Base configuration](https://huggingface.co/Qwen/Qwen3.5-4B/resolve/851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a/config.json)
- [Multimodal adapter configuration](https://huggingface.co/cua-ai/cua-s1-4b-0.2/resolve/16818868b0cc7813808aae4e87b417657046ab79/multimodal/adapter_config.json)
- [Base second shard, containing the vision tensors](https://huggingface.co/Qwen/Qwen3.5-4B/resolve/851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a/model.safetensors-00002-of-00002.safetensors)
- [Multimodal adapter safetensors](https://huggingface.co/cua-ai/cua-s1-4b-0.2/resolve/16818868b0cc7813808aae4e87b417657046ab79/multimodal/adapter_model.safetensors)

The tensor inventories retain only the `shape` and `dtype` fields of the visual
entries in those safetensors headers; byte offsets and language tensors are not
part of the oracle.
